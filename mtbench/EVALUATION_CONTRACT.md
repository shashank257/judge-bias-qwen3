# MT-Bench formatting-bias evaluation contract — independent draft v1

**Status: draft for team approval, not preregistered.** This is based on the uploaded project proposal and the separate groupmate's midterm report; it does *not* reproduce their unavailable harness or evaluation contract.

## Research question

Does editing only Markdown formatting (bolding the first four words) alter pairwise LLM judgments when answer text is otherwise held fixed? Compare format effects with answer-order effects and repeated-input variability. This is a *narrow emphasis-format* intervention, not a general test of Markdown removal.

## Source and eligibility

Use the CSV generated by `prepare_mtbench_pilot.py` (`mtbench_pilot_100.csv`). Each row is an answer pair with an aggregated majority human winner, excluding ties. A manual audit for semantic preservation is required before submitting a full pilot. The data-prep script is separately provided; the current package does not change it.

**Important: multi-turn risk.** The provided data-preparation logic builds `question_context` from conversation A only; candidate B might have a distinct earlier assistant response. Default evaluation excludes `turn != 1`. If second-turn pairs are added back, reconstruct *candidate-specific* conversation histories and decide how to present them to judges, then document the protocol change. Do not use `--include-multiturn` for confirmatory results without resolving this.

## Judge and prompting

Judge: local or hosted OpenAI-compatible chat-completions endpoint. Record exact checkpoint, backend, quantization, thinking setting, decoding parameters, prompt, date and hardware. Default temperature 0, maximum 96 output tokens; some Qwen thinking configurations need more tokens and backend-specific settings. For baseline comparison, use the same judge prompts/settings across formats. This draft prompt is **not identical** to the groupmate's standard MT-Bench prompt; the report does not include their full text.

A forced two-way verdict must be exactly `[[A]]` or `[[B]]`, representing displayed order, and is mapped back to original answer identities A/B. Invalid outputs are retried and logged. No ties. All raw model responses and request messages are retained in JSONL.

## Conditions and repetitions

Per eligible pair: eight format × order cells (A/B: PP, MP, PM, MM; shown AB and BA), plus one exact repeat of PP/AB and PP/BA, giving **10 calls per pair per judge configuration**. The two repeats are a limited noise-floor probe; if judge stochasticity depends on formatting, repeat more cells in a sensitivity study. This differs from groupmate's all-Markdown repeated baseline because our original answers are plain.

The harness assigns stable job IDs, appends JSONL after every call, resumes completed evaluations, and does not send network requests without `--execute`.

## Measurements

- **Format flip**: fraction of PP-to-MP or PP-to-PM matched comparisons whose *original A/B winner* changes while order stays fixed.
- **Position flip**: compare PP/AB with PP/BA, mapped to original A/B identities.
- **Noise**: PP/AB vs its repeat and PP/BA vs its repeat, exactly the same request.
- **Markdown preference**: percentage choosing the markdown-styled answer when exactly one answer is styled; interpret jointly with answer-quality and order baselines, as 50% is not necessarily an unbiased null in unbalanced datasets.
- **Human agreement**: compare first-run PP verdicts to human-majority labels. These labels reflect original displayed responses, not a new format-neutral human evaluation.
- Report denominators, missing outputs, raw flip and noise separately, and *descriptive* excess flip = flip − noise. Do not assume that simple subtraction provides a causal correction.
- Cluster-resample by `question_id`, not by the 10 calls. Run a larger sample for confirmatory claims; the currently selected 100 pairs span fewer unique questions.

`analyze_results.py` provides preliminary clustered bootstrap intervals for the five principal metrics. It does not implement full preregistered testing, Cohen's kappa, Holm corrections, McNemar, or mitigation comparisons; those require a subsequent analysis stage.

## Quality and reproducibility

Before full run: validate pilot pair IDs, first-turn contexts, exact text reconstruction, stylistic audit, and both display orders in a five-pair smoke test. Freeze the CSV checksum, system/user prompts, exact model IDs, inference mode, quantization, decoding settings, and code commit for final analysis. The current generated CSVs were not uploaded, so no judge run has been performed in this package.
